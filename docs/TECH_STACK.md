# 기술 지도

프로젝트에서 실제로 선택해 사용 중인 기술과 그 이유를 역할별로 기록한다.
아직 필요하지 않아 결정하지 않은 기술은 기록하지 않는다.

각 항목은 아래 형식으로 추가한다.

```md
### 기술 또는 도구 이름

- 역할: 이 프로젝트에서 무엇을 담당하는가
- 선택: 사용 중인 버전, 도구, 또는 방식
- 이유: 현재 프로젝트에서 이 선택이 적절한 이유
- 상태: 검토 중 | 사용 중 | 대체됨
- 재검토: 어떤 상황에서 다시 결정할 것인가
```

## 1. 클라이언트 애플리케이션

브라우저 웹과 미래의 모바일 앱처럼, 사용자가 직접 사용하는 화면을 다룬다.

### React

- 역할: 브라우저에서 글쓰기 화면을 만든다.
- 선택: React
- 이유: 웹 프론트엔드 경험을 쌓고, 향후 React Native 학습과 연결할 수 있다.
- 상태: 사용 중
- 재검토: 웹 화면 구조가 복잡해져 별도 도구가 실제로 필요해질 때

## 2. 서버 애플리케이션

웹 요청을 받고, 데이터를 처리하며, AI 피드백을 연결하는 서버를 다룬다.

### 서버 아키텍처

- 역할: 서버 코드의 책임을 나누고, 기능이 늘어날 때 구조를 유지한다.
- 선택: 단일 Spring Boot 애플리케이션으로 시작하고, 기능별 패키지 구조를 사용한다. 각 기능에는 실제 책임이 생길 때만 Controller, Service, Repository를 추가한다.
- 이유: 현재 MVP는 하나의 서버로 충분하며, 기능별 구조는 글 저장과 AI 피드백이 추가돼도 관련 코드를 한곳에 모을 수 있다. 불필요한 인터페이스와 추상화를 미리 만들지 않는다.
- 상태: 사용 중
- 재검토: 기능별 독립 배포가 필요해지거나, 외부 기술 구현체를 교체·복수 지원해야 할 때

### Java

- 역할: 서버 애플리케이션을 작성하고 실행한다.
- 선택: Java 21
- 이유: 장기 지원 버전이며 Spring Boot 4.1.1과 호환된다.
- 상태: 사용 중
- 재검토: 배포 환경의 Java 버전을 정할 때

### Spring Boot

- 역할: HTTP 요청을 처리하는 API 서버를 만든다.
- 선택: Spring Boot 4.1.1
- 이유: 현재 안정 버전이며, 내장 웹 서버를 포함해 최소 설정으로 서버를 실행할 수 있다.
- 상태: 사용 중
- 재검토: 없음

### Gradle

- 역할: 서버의 의존성, 빌드, 테스트 작업을 관리한다.
- 선택: Gradle Groovy DSL
- 이유: Gradle 기반 프로젝트를 직접 경험하고, 서버의 빌드 과정을 관리한다.
- 상태: 사용 중
- 재검토: 없음
